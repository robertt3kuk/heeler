## Problem
A session's environment depends on who started `hutand`: from a terminal it inherits that shell's exports (virtualenvs, `PWD`, tool shims); from the desktop or launchd it gets the bare GUI environment. Terminal.app, iTerm2 and Ghostty start every tab from the user's login environment instead.

## Scope
`crates/terminal`, `crates/daemon` (config + spawn), `crates/settings` + `crates/desktop` (terminal settings → `TerminalSpec`), `crates/cli` only if a flag is needed, docs (`docs/shell-integration.md` or a new § in `docs/architecture.md`, settings docs in `docs/design.md`). **No protocol change**: use the existing `TerminalSpec.command` / `env`.

## Contract
- `daemon.toml [terminal] env_inherit = "login" | "daemon"` (default `login`).
- `login`: the child starts from an **empty** environment plus: `HOME`, `USER`, `LOGNAME`, `SHELL` from the account (`getpwuid_r`); `TMPDIR` from `confstr(_CS_DARWIN_USER_TEMP_DIR)`; `LANG`/`LC_*` and `__CF_USER_TEXT_ENCODING` from the daemon only when set (else `LANG` from the user's locale, `defaults read -g AppleLocale` → `xx_YY.UTF-8`, cached); `PATH` from `/usr/libexec/path_helper -s` output (parsed, not eval'ed; cached; fallback `/usr/bin:/bin:/usr/sbin:/sbin`); `SSH_AUTH_SOCK` from `launchctl getenv SSH_AUTH_SOCK` (cached at daemon start, refreshed if the socket vanished). The login shell (`-l`) builds the rest as usual. `daemon`: today's behavior.
- Precedence, lowest to highest: base (above) < `TerminalSpec.env` from the client < terminal/integration variables (`TERM`, `COLORTERM`, `TERM_PROGRAM`, shell-integration variables) < daemon-managed `HUTAN_*`. An explicit `SHELL` in `TerminalSpec.env` still selects the shell (existing `default_shell` rule).
- Desktop settings namespace `terminal`: `shell` (string; empty = account login shell) and `env` (table of strings), both overridable by the workspace layer `.hutan/settings.toml`. The desktop resolves them for the target workspace and puts them into `TerminalSpec` (`shell` → `env.SHELL`, `env` merged). Values are passed through, never logged.
- Restore: unchanged (`persistable_spec` still drops secret-looking names); a restored session gets a fresh base env.
- Agent sessions started by the daemon (Codex app-server, gateway) are not affected.

## Acceptance
- Unit tests: env assembly and precedence (pure function over an injected "system facts" struct: account, temp dir, path_helper output, launchctl values), `path_helper -s` parsing (both `PATH="…"; export PATH;` and `setenv` forms), daemon-env leakage absent in `login` mode (a sentinel variable set in the daemon process does not reach the child), `daemon` mode keeps it.
- Daemon test: a session running `/usr/bin/env` shows the expected keys, `HUTAN_*` win over a client-supplied `HUTAN_SESSION_ID`, the sentinel is absent.
- Desktop GPUI/store test: workspace `.hutan/settings.toml` `terminal.env` overrides the user layer and reaches `session.create`.
