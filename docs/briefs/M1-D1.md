## Contract

### Sessions (M1.5)
- `session.create` with `SessionSpec::Terminal`: workspace defaults to `default`; unknown workspace → `not_found`. Spawn via `staffy-terminal` with env from the spec plus daemon-managed `STAFFY_SOCKET`, `STAFFY_SESSION_ID`, `STAFFY_WORKSPACE_ID` (these win). `TerminalId`s are monotonically increasing per epoch, starting at 1. Title defaults to argv[0] basename or the shell name. Spawn failure → session `failed` with reason (still listed) and the request returns it in `SessionCreated`.
- Lifecycle through `staffy_core::SessionState::transition` only (Starting → Running on spawn; exit → `Exited{code,signal}`; stop → `Stopped`). Every change emits `session.updated`; process exit also emits `session.exited`.
- `session.stop`: `terminate(3 s grace)`, then `Stopped`. `session.restart` (only from ended states): respawn the same spec, new `TerminalId`, same `SessionId`. `session.rename` updates title. `session.list` (optional workspace filter) and `session.snapshot` include sessions with the current `seq`.
- An exited session keeps its terminal so clients can still attach and read the final screen until restart.
- Terminal metadata → events: title → `terminal.title` (and session title if the user never renamed it), bell → `terminal.bell`, notification → `terminal.notification`, cwd → session `cwd` + `session.updated`. Prompt marks are ignored for now.
- `workspace.close`: the `default` workspace cannot be closed (`invalid_state`); a workspace with live sessions cannot be closed (`invalid_state`).
- `daemon.shutdown { stop_sessions: false }` with live sessions → `invalid_state`; with `true` (and on SIGTERM/SIGINT) terminate all sessions (grace 3 s, concurrently), then exit.

### Attach and render (M1.4)
- `terminal.attach { terminal_id, size? }`: optional resize first; create a per-(connection, terminal) attachment with its own `RenderTracker`; enqueue the binary `TerminalRender::Snapshot` frame **before** the `TerminalAttached { frame }` response. Attaching twice from one connection replaces the previous attachment.
- Render pacing: an attachment has credit 1. After sending a render it waits for `terminal.ack { frame }` equal to the last sent frame number; then, when damage occurs (or immediately if damage happened meanwhile), it calls `Terminal::render(&mut tracker)` and sends the result (frame or snapshot). Coalesce: at most one render per ~8 ms per attachment. No render is ever queued while credit is 0, so a non-acking client costs O(screen) memory and never trips the slow-consumer limit.
- `terminal.detach`, connection close, and session restart drop attachments (restart: clients must re-attach to the new terminal id; `session.updated` carries it).
- `terminal.resize`: PTY size shared by all clients, last writer wins; attachments receive a snapshot (terminal crate handles that via `render`).
- `terminal.history`: delegate to `Terminal::history`, return `TerminalHistoryRows`.
- Input: kind=2 frames for a terminal go through a per-terminal bounded input queue drained by a task that calls `write_input` on a blocking-safe path (`spawn_blocking` or dedicated thread); if that queue is full the sending connection's reader awaits (backpressure on the input source only). Input for unknown or ended terminals is dropped with a debug log.
- Unknown `terminal_id` in any terminal method → `not_found`.

## Acceptance
Integration tests in `crates/daemon/tests/` over a real socket with `staffy-client` on temp `STAFFY_HOME`:
1. create `sh -c 'echo hello; exec cat'`, attach, snapshot contains `hello`; `send_input("ping\r")` → a later render contains `ping`.
2. ack pacing: with a flood (`sh -c 'yes | head -c 20000000; exec cat'`) and no acks, the client receives exactly one render after the snapshot; after acking, the next render reflects the latest screen; daemon stays responsive to `daemon.status` throughout.
3. two clients attached to one terminal both observe the same output; one detaches, the other keeps receiving.
4. process exit → `session.exited` with code and `session.updated` state `exited`; attach after exit still returns the final screen.
5. stop → `stopped`; restart → new terminal id, output from the new process.
6. resize via `terminal.resize` → attached client gets a snapshot with the new size; `stty size` inside shows it.
7. history after `seq 1 300` returns rows newest-first.
8. title via `printf '\033]2;hey\007'` → `terminal.title` event and session title updated.
9. `workspace.close` refusals; `daemon.shutdown{stop_sessions:false}` refusal with a live session; `stop_sessions:true` terminates children (pid gone) and removes the socket.
`just check` green.
