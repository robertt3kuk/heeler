## Contract
- **Attachment kinds** (additive): `image { path? | data_base64?, media_type }` (PNG/JPEG/GIF/WebP, ≤ 5 MiB after reading; data inline only from the desktop clipboard, ≤ 5 MiB), `pasted_text { text }` (≤ 256 KiB), and the existing `file { path, range? }` now accepted for **every** chat kind. Directories are refused (`bad_request`).
- **Where the daemon reads**: a `file`/`image` path is read by the daemon, confined to the session's allowed roots *plus* paths the user explicitly dropped/picked (the desktop sends them; the daemon trusts a desktop/CLI origin, refuses agent-origin attachments with `forbidden` — ADR 0016 origins). Secrets: text attachments pass the existing redactor; images are not redacted (documented).
- **Delivery per backend**:
  - ACP harnesses (OMP, Claude): `image` content blocks when `promptCapabilities.image`, else refused with a clear `unsupported` message; text files/pasted text as `resource` (embedded context) when `embeddedContext`, else as quoted text blocks (existing M16 format).
  - Codex app-server: images as `localImage` (path; clipboard data written to a temp file under `$HUTAN_HOME/tmp/` and cleaned when the turn ends), text as quoted text.
  - Direct providers / assistant: images as the provider's image content (OpenAI `image_url` data URL, Anthropic `image` base64, Ollama `images`) when the model supports vision per the provider's model list, else `unsupported`; text as today.
- **Journal**: attachments metadata (kind, name, size, media type, truncated) recorded with the user message; image bytes are not journaled (path + hash only).
- **Desktop composer**: drag and drop files/images from Finder onto the chat (whole chat view is a drop target with a highlighted overlay); ⌘V of an image (clipboard image) or of file URLs attaches; ⌘V of text longer than 2 000 chars or 40 lines becomes a `pasted_text` chip ("Pasted · 312 lines") that expands on click; a `+` menu gains "Attach file or image…" (NSOpenPanel via GPUI `prompt_for_paths`); chips show a thumbnail for images, an icon + name + size for files, and an ✕; Backspace at the start of an empty composer removes the last chip. Refusals (too big, unsupported by the model) show inline on the chip before sending, using the session's known capabilities.
- **CLI**: `hutan chat send <session> --attach file:<path> --attach image:<path> "text"`.
