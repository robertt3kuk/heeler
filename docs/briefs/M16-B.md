# M16-B: assistant panel and explicit context chips (roadmap M16, part 2)

Agent: implementer · Depends on: M16-A (protocol 0.12) and M5-B merged · Branch: slice/M16-B

## Context
Read `AGENTS.md`, `docs/roadmap.md` § M16, `docs/assistant.md`, `docs/gateway.md` § Desktop, ADR 0010, and the actual merged M16-A protocol. Reuse the M4/M5 transcript/composer and existing panel registry; do not create a second chat implementation.

## Scope
`crates/desktop`, additive client helpers if required. No daemon/protocol changes; report contract gaps. Parent owns `docs/status.md` and `docs/roadmap.md`.

## Behavior
- Register an `assistant` panel, movable like other panels. ⌥Space opens/focuses it in the workbench; OS-global registration belongs to M6. Expose the same action in ⌘K. Opening an assistant never creates a PTY or starts a vendor agent process.
- Choose Global (Home) or Active workspace scope. Call `assistant.open`; display the returned direct-chat session using the existing chat model/view. Scope changes retain the other conversation and never silently transfer attachments between workspaces.
- Empty/unconfigured state names the missing provider/model prerequisite and links to Models settings. Use the daemon's actual configuration contract; never silently choose a different paid provider.
- Context is opt-in per message: `@shell` offers recent output or finished blocks from available terminals; `@omp`/`@agent` offers reported/indexed agent transcripts; `@file` selects a workspace-local path with an optional line range; `@search` attaches a bounded history query. Also provide an explicit Attach menu so the feature does not depend solely on parsing mention text.
- Chips display kind, source and requested bounds before send; they are removable. Send structured M16-A attachments, not client-side file/transcript reads. Show the daemon's resolved size/truncation metadata and permission errors. An unattached source must never be read or added to the prompt.
- Send-to-assistant from terminal blocks uses the existing block action machinery and structured block attachment. Persist conversations through the existing journal; history results carrying `session_id` open the assistant/chat rather than spawning a terminal.

## Acceptance
GPUI scenarios against an in-process daemon, `MemoryStore`, and the reusable loopback HTTP mock:
1. Open Global assistant, send and stream; no terminal is created. Switch workspace scope and verify each scope retains its own transcript.
2. Add/remove each supported context chip; the mock's assembled prompt contains only the selected sources. Permission refusals and truncation metadata are visible.
3. A file chip cannot escape workspace roots (including symlinks); the desktop never opens the file itself.
4. Search a persisted assistant conversation, open its hit, and continue the same conversation.
5. Unconfigured provider/model shows the prerequisite, without a fallback model call.

Run a native smoke with an in-process `MemoryStore` daemon (no login keychain, paid APIs, screenshots or permission prompts); report the actual exercised surface and visual limit. Run `just check` once the slice is complete. Commit locally, never push.

## Rules
Absolute worktree paths; inline `HUTAN_HOME=<temp dir>` on every Hutan command. No real agent transcripts/configs, `/tmp/hh-*`, login keychain, resets or published-history rewrites. Stop every process started, including a daemon whose startup command times out.
