## Decision (with the user)
Hutan works like Orca/Paseo by default: the daemon starts with the app and nothing starts at login. Running the daemon at login and keeping it after quit are separate **opt-in** choices, offered in a first-run setup and in Settings.

## Scope

No daemon/protocol changes.

## Contract
- **Two settings, both default `false`:**
  - `app.keep_running` — "Keep the daemon running after Hutan quits": Quit leaves `hutand` running (no confirmation about stopping sessions), **no** login item. It stops when the user stops it (Daemon menu / `hutan daemon stop`) or at logout.
  - `app.start_at_login` — "Start Hutan's daemon when you log in": registers the bundled LaunchAgent via SMAppService (today's keep-running behavior: `RunAtLoad`, `KeepAlive {Crashed}`), shows its status (enabled / requires approval + Open Login Items / not registered / not found), available only from Hutan.app. While registered, quit never stops the daemon and the desktop connects to the launchd daemon (`start_held`). Turning it off unregisters.
  - Migrate the existing meaning: a user who had `keep_running = true` (it meant the login item) gets `start_at_login = true` and `keep_running = true` on first read (settings diagnostic noting the migration); nothing registers without that.
  - Quit dialog with live sessions: "Stop Sessions & Quit" / "Keep Running in Background" (sets `keep_running`, not the login item) / "Cancel". Menu bar menu and Daemon menu show both toggles.
- **First-run setup** (shown once, when no `app.setup_done = true`; reopenable from ⌘K "Hutan: Run Setup…" and Settings → General → "Run setup again"): a centered sheet in the v2 style (surface card, 12 px radius, generous spacing, mascot images per step, serif headline, sans body, primary/secondary buttons, step dots, Back / Continue / Skip setup). Steps:
  1. **Welcome** — mascot (`angle-front`), "code from the canopy", one sentence about what Hutan is.
  2. **Look** — appearance System / Light / Dark with live preview, density Compact / Comfortable.
  3. **Agents** — detected harnesses (OMP first, Claude Code, Codex) with installed / logged-in state from `account.list`; "Log in…" opens the harness login session (M8-B); link to install docs when missing. Assistant: enable/disable and pick its backend (default OMP when logged in, else none), per M8-B.
  4. **Background** — the two toggles above with plain explanations ("Like Orca/Paseo, Hutan's daemon runs while the app runs."), both off; notifications: "Allow notifications" button that triggers the permission request only when pressed (native daemon posting, M6-B) and shows the result.
  5. **Command line** — "Add `hutan` to your PATH": symlink `~/.local/bin/hutan` → `Contents/MacOS/hutan` of the running bundle (only when `~/.local/bin` exists and the target is absent or already our symlink; otherwise show the command to run) — off by default; shell integration note.
  6. **Done** — mascot (`state-success`), "Open a folder" (⌘O) / "New terminal" buttons.
  Every choice is written to settings when the step is left; Skip writes `setup_done` and leaves defaults.
- Settings → General shows the same toggles; the settings schema/docs describe them.
