## Problem
The user wants an Activity-Monitor-like view of everything Hutan runs and to stop or kill any of it: a whole session, one process inside it (a runaway build), an agent turn, or a single subagent.

## Contract
- **Process tree per session**: from the session's PTY child pid, all descendants (macOS `proc_listchildpids` / `proc_pidinfo` via libc: pid, ppid, name, command line (truncated to 512 chars, secret-looking `--token=…`/`KEY=…` arguments redacted like the index redactor), state, CPU % (delta of `pti_total_user+system` between samples), resident memory, threads, start time). Chat sessions: the harness process (Codex app-server, ACP agent) and its descendants. The daemon itself (`hutand` pid, RSS, CPU) as one row.
- **Sampling only while watched**: `resources.subscribe {interval_ms ≥ 1000, default 2000}` starts sampling, event `resources.updated {sessions: [{session_id, processes: [...], totals}], daemon}`; it stops when the last subscriber leaves. `resources.list` returns one fresh sample. Bounded: at most 512 processes per session, 4096 total; beyond that a `truncated` flag.
- **Agent tree link**: `AgentNode` gains optional `pid` (additive): set from `agent.report --pid` (the OMP extension and Claude hooks can report their own pid where they run as a process) and from adapters that know it (Codex subagent threads have none: leave empty). The resources view lists, per session, the agent nodes with their pids when known.
- **Actions** (mutations; agent-originated ones go through M8-C's policy):
  - `session.stop` (exists), `session.kill {session_id}` (SIGKILL the process group immediately).
  - `process.signal {session_id, pid, signal: term | kill | int | hup | stop | cont}`: only for a pid that is the session's child or one of its descendants at the time of the call (re-verified from a fresh sample; otherwise `forbidden`); never `hutand` itself or any pid outside Hutan's sessions.
  - `agent.interrupt {session_id, node_id?}`: the root (no node) interrupts the running turn (Codex `turn/interrupt`, ACP `session/cancel`, direct chat stop); a subagent node: Codex child thread → `turn/interrupt` on that thread; a node with a known `pid` → SIGINT then, if `force`, SIGTERM; otherwise `invalid_state` naming that this harness cannot stop a single subagent (the root can still be interrupted).
  - Every action is audited (who, what, result).
- **CLI**: `hutan ps [SESSION] [--watch] [--json]` (tree per session: pid, CPU, RSS, command; agent nodes marked), `hutan kill SESSION [--pid PID] [--signal term|kill|int|…]`, `hutan agent interrupt SESSION [NODE] [--force]`; `hutan top` = `ps --watch` sorted by CPU.
