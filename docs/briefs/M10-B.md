## Contract
- **Line coordinates**: blocks reference absolute line numbers in the terminal's output (monotonic per terminal, survive scrollback eviction: a block whose prompt line was evicted is dropped or marked truncated).
- `Block { id: u64 (monotonic per terminal), prompt_line, command_line: Option<u64>, output_start: Option<u64>, end_line: Option<u64>, command: Option<String> (text between B and C from the grid), exit_code: Option<i32>, started_at_ms, finished_at_ms, cwd: Option<PathBuf> (from OSC 7 at A), state: prompt | running | finished | truncated }`.
- Engine side: the terminal records mark positions as the sniffer sees them, tied to the cursor's absolute line at the time the engine has processed the bytes before the mark (marks are emitted between engine feeds; keep ordering exact even when a mark is split across reads).
- Alternate screen: marks while the alt screen is active are ignored; a block's output ends where the program left the alt screen.
- `ESC[3J` / `clear`: blocks whose lines were erased become `truncated`.
- Bounded: at most 2 000 blocks per terminal (oldest dropped).
- Protocol 0.4: request `terminal.blocks { terminal_id, before_id?: u64, limit ≤ 500 }` → `{ blocks: [Block] }` newest first; event `terminal.block { terminal_id, block }` on every state change (prompt started, command started, finished); `terminal.block_text { terminal_id, block_id, part: command | output, max_bytes }` → `{ text, truncated }` (plain text across hot + cold, used for copy and "send to agent").
- `SessionInfo` unchanged; desktop/cli can call `terminal.blocks` on attach.
