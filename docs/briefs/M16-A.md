## Contract
- **Assistant sessions** are direct chats (M5-A) with `chat.agent = "assistant"` and a scope: `global` (lives in Home) or `workspace` (one default assistant per workspace; more can be created). `assistant.open { scope, workspace_id? }` returns the default assistant session for that scope (creating it on first use with the provider/model from settings `assistant.provider`, `assistant.model`; error `invalid_state` with a hint when none configured).
- **Context providers** (read-only, bounded, explicit): a message may carry `attachments: [Attachment]` where `Attachment = { kind: shell_block {terminal_id, block_id} | shell_recent {terminal_id, lines ≤ 500} | agent_transcript {session_id, last_turns ≤ 20} | file {path, range?} | search {query, limit ≤ 10} }`. The daemon resolves each into a text part: `shell_*` via the block index / scrollback (`terminal.block_text` path), `agent_transcript` from the M4 journal (Codex/direct/assistant sessions) or an external transcript via the M17 index rows for that session (`omp`/`claude`/`codex` hits), `file` read from disk only under the workspace roots (refuse others with `forbidden`), `search` via `history.search`. Each resolved part is wrapped with a header (`[shell: <cmd> · exit 0 · 120 lines]`), redacted with the M17 redactor, truncated to its share of `assistant.context_budget_chars` (default 60 000, split evenly, truncation noted in the header), and journaled as part of the user message (so the conversation is reproducible and visible).
- **Permissions**: per-workspace settings in daemon config `[assistant.context]` `shell = true`, `agents = true`, `files = true`, `search = true`; global scope has `files = false` by default (Home folder only). A disallowed attachment → `forbidden` with which setting gates it. Nothing is ever read without being attached.
- **Indexing**: chat journals (Codex, direct, assistant) feed the M17 index as source `staffy` with roles user/assistant/tool and `resume` = focus the session (no argv); `history.search` hits for them carry `session_id` (additive field) so clients can open them.
- **Protocol 0.12**: `assistant.open`, `assistant.list { scope?, workspace_id? }`, `chat.send` gains optional `attachments`; `chat.event` user message events carry `attachments_meta` (kind, label, chars, truncated) — never the raw text beyond what is journaled; `HistoryHit.session_id?` (additive). Golden fixtures.
- **CLI**: `staffy ask "<question>" [--ws <id|name>] [--attach block:<terminal>:<block> | recent:<terminal>:<n> | agent:<session> | file:<path> | search:"<q>"]…` (streams the answer; uses the scope's default assistant), `staffy assistant ls|open`.
