## Design constraints
- **Opt-in**: `daemon.toml` `[history] enabled = false` by default; `range_days = 0|30|90` (0 = all); per-source toggles. Disabled ⇒ no file is read. Index lives in its own DB `$HEELER_HOME/index.sqlite` (separate from `heeler.sqlite` so Clear is a file delete + recreate), WAL, own writer.
- **FTS5 + BM25** (rusqlite `bundled` already includes FTS5 — verify): one row per message/chunk with columns `body` (text), `idents` (paths, commands, symbols extracted by a cheap tokenizer: `/`-paths, `--flags`, `crate::paths`, backticked spans), plus unindexed metadata (source, session key, role user|assistant|tool|command|output, timestamp, cwd/project, title). Ranking: `bm25(fts, w_body, w_idents)` with role weights (user > assistant > tool) applied in SQL; snippet via `snippet()`. Chunk long tool outputs (≤ 4 KiB per row, cap per session).
- **Incremental scanning**: FSEvents (`notify` crate with the macOS FSEvents backend) on the source roots + a `sources` table of per-file `(path, size, mtime, offset, format_version)`; JSONL files are read from the stored offset only (append-only), rewritten/truncated files re-indexed; startup does one stat pass (no content reads for unchanged files); never periodic full rescans. Bounded CPU: indexing runs at low priority (a dedicated thread with `setpriority`/QoS utility), batched transactions, yields between files.
- **Secrets**: run every indexed text through a redactor for obvious secrets (reuse/extend the secret-name heuristics from M3-A; add patterns for `sk-…`, `ghp_…`, `AKIA…`, `-----BEGIN … PRIVATE KEY-----`, `Bearer …`) before insert; documented as best-effort.
- **Sources (adapters, each versioned, each with synthetic fixtures — NEVER commit real transcripts; build fixtures by hand in the observed shapes)**:
  - Heeler: terminal blocks (command + output text via the block index at `D`), agent reports (state changes as rows).
  - Claude Code: `~/.claude/projects/<cwd-slug>/<session>.jsonl` (lines with `type` user/assistant, `message.content` parts incl. tool_use/tool_result, `sessionId`, `cwd`); resume `claude --resume <sessionId>`.
  - Codex: `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl` (`session_meta` with `id`, `cwd`; `response_item`/`event_msg` payloads); resume `codex resume <id>`. Do not read `~/.codex/*.sqlite` in this slice.
  - OMP: `~/.omp/agent/sessions/<cwd-slug>/<…>.jsonl` (first line `type:title`; inspect the shapes); resume `omp --resume=<id>`.
  - OpenCode (`~/.local/share/opencode/opencode.db`, SQLite, read-only `?mode=ro`, tables `session`, `message`, `part`): include only if the schema is straightforward; else document as deferred.
  Roots overridable in `daemon.toml` (tests point them at temp dirs).
- **Protocol 0.8**: `history.search { query, limit ≤ 100, sources?, roles?, project?, since_ms?, until_ms? }` → `{ hits: [{ source, session_key, title, cwd, role, ts_ms, snippet, score, resume_argv? }] }` grouped by session (best hit per session + count); `history.status` → `{ enabled, sources: [{ name, files, rows, last_indexed_ms, errors }], db_bytes }`; `history.clear`; `history.rebuild`. `resume_argv` validated with the M3-B rules.
- **CLI**: `heeler search "<query>" [--source claude|codex|omp|opencode|heeler] [--since 7d] [--json] [--resume N]` (`--resume` opens a new terminal session in the hit's cwd running its resume argv via `session.create`); `heeler index status|enable|disable|clear|rebuild`.

## Acceptance
- Adapter tests on synthetic fixtures (append → only new lines read; truncate → re-index; malformed lines skipped and counted); ranking tests (identifier query like `cargo test -p daemon` finds the command row first; role weighting); redaction tests; FTS5 availability test.
- Daemon test: enable on temp roots, write fixture files, FSEvents-driven index within a bounded wait, `history.search` finds them, `history.clear` empties, disabled ⇒ zero file reads (assert via the sources table/metrics).
- Perf note in `docs/history-index.md`: index a generated corpus of ~100k messages; report time, DB size, idle CPU after indexing (must be ~0).
- Manual (orchestrator-approved only): do **not** point the index at the user's real `~/.claude`/`~/.codex`/`~/.omp` during the slice; use copies in a temp dir if you need realistic data, and never commit them.
