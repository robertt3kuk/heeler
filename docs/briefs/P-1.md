## Contract
1. **Measure first** (release build, `just bench` harness, temp `HUTAN_HOME`, seeded data via `xtask seed` or new seeding): add scenarios and record before numbers in `docs/perf.md`:
   - **B3** idle CPU with the default layout *plus* sidebar (20 projects, 3 workspaces, 60 sessions), Tasks, Resources (it polls) and Agents panels open: daemon + desktop ≤ 0.5 %.
   - **B7** chat transcript: open a chat with 5 000 journal events (messages with markdown + code, tool cards, diffs): time to first paint ≤ 150 ms, scroll p95 frame ≤ 1 frame + 2 ms, RSS growth ≤ 60 MB.
   - **B8** streaming: a reply streamed at 200 deltas/s for 20 s: p95 frame ≤ 1 frame + 2 ms, no frame > 50 ms, keystroke latency in the composer p95 ≤ 16 ms while streaming.
   - **B9** sidebar: 300 sessions / 40 projects, filter typing p95 ≤ 16 ms per key, drag reorder frame p95 ≤ 1 frame + 2 ms.
   - **B10** session switch: ⌘1…⌘9 / ⌘P jump between 10 terminals and 5 chats: p95 ≤ 50 ms to the new item's first frame.
   - Use `sample(1)` / `HUTAN_TRACE_LATENCY` to attribute time (layout, text shaping, markdown parse, cloning big state, re-render of whole lists).
2. **Fix** what misses, typical suspects to check against the profiles (do not assume): whole-list re-renders without `uniform_list`/virtualization, markdown re-parsed every frame (cache per message + width), cloning `StoreState`/transcripts per render, timers that tick while hidden (Resources/monitor durations should stop when not visible), `cx.notify()` storms from every daemon event, text shaping of long lines, images decoded per frame (R-1 thumbnails: decode once, cache).
3. **Keep budgets in the gate**: the cheap, deterministic parts as unit/GPUI tests (e.g. markdown cache hit, virtualization renders O(visible)), the timing ones in `just bench` only (not in `just check`).
4. `docs/perf.md`: new rows with before/after medians of 3 runs, method notes, fixes section entries.
