# Hutan user-test round 2 — 2026-10-17

## Executive result

The supplied test bundle is substantially better at the round-one workflows. **All four original major findings have a working fix in the exercised path:** existing terminal tabs reconnect after a daemon restart; Start defaults to Plain terminal and confirms a billable launch; automatic hook installation is off; Command executes shell composition correctly. The complete **Command → new worktree → diff → inline comment → Request changes → Accept → Commit all → Merge → remove worktree and branch** journey worked with real local Git changes and mouse interaction.

**No application-wide blocker observed. Three major findings remain in this pass:** setup is not keyboard-modal (N1), synthesized Unicode becomes incorrect characters in Hutan-owned inputs (N2), and normal-mode-off/default text fields lack working paste (N3). N2 and N3 prevent ordinary search/composition through the supplied driver unless a working clipboard path is used. Turning Vim mode on made paste work in the simple search fields, allowing the sidebar, History and Resources journeys to continue. This is a workaround, not a pass for the default experience.

There are also smaller failures: Select All does not replace Jump text (N4), Resources row menus never become visible in the exercised paths (N5), and narrow Changes content still hides the commit affordance and most of the diff despite the repaired toolbar (N6). Full chat-composer editing and the Resources **kill confirmation** are not certified; see the journey table. No model turn was sent.

### How to interpret the times

Times are observed **tool/subprocess wall time**, not frame latency or human task-completion benchmarks. Inspection pauses between tool calls are excluded. Cua median calls in this run were approximately **4.09 s hotkey, 4.82 s type_text, 5.70 s click, 3.25 s capture**. Consequently, a 10-second two-action journey does not mean the application spent ten seconds computing. CLI actions commonly returned in 5–30 ms. A few evaluation cells hit their own deadline while a driver call was in progress; this alone is not evidence of an app hang. No sustained app hang was observed that warranted `sample <pid> 2`.

## 3. New findings

### N1 — Setup looks modal but lets keyboard input execute in a terminal behind it

**Severity: major. Area: onboarding / modal focus and key dispatch.**

**Exact steps:** Launch into incomplete setup, or run `ui run workbench::RunSetup`; leave the welcome card visible. Send ⌘T, type `printf 'R2_MODAL_HOTKEY_LEAK\n'`, Return. Send physical Escape via foreground `hotkey ["escape"]`.

**Expected:** A visible modal owns keyboard focus and blocks workbench/terminal dispatch. Escape either closes/skips an optional setup flow or has explicit documented behavior; it must not leave an apparent modal over an active underlying shell.

**Actual:** A new terminal tab appears behind the dimmed sheet and executes the command, including its output. The setup welcome card stays in front. Physical Escape also leaves it present. Mouse **Skip setup** is a usable escape path, so this is not an application-wide blocker.

**Evidence:** **E/r2-02-setup-input-leak.png**, **E/r2-89-setup-real-escape.png**, **E/r2-90-setup-physical-leak.png**; session counts and command input in observations. The integrator said a fix was being prepared; **that fix was not installed or retested in this pass**. Probable cause [INFERENCE]: setup overlay lacks modal focus/key interception.

### N2 — Synthesized Unicode text becomes repeated Cyrillic characters in Hutan inputs, but not terminals

**Severity: major. Area: shared text inputs / platform text-input handling.**

**Exact steps:** With the supplied foreground Cua driver, open ⌘P and call `type_text` with **Round two**. Repeat in Start Prompt, sidebar filter or project rename. For comparison, send a `printf` command through `type_text` into a terminal.

**Expected:** The actual Unicode string provided to text entry appears in the field, regardless of the active layout. Terminal and Hutan text fields should accept the same provided text.

**Actual:** Jump shows repeated **ф** characters (space positions preserved); sidebar filter and launcher Prompt do likewise. Rename replaces the old name but produces seven `ф` characters for **Orchard**. Terminal receives and executes the intended ASCII correctly. Pasting through working rich-field/Vim paths preserves English text.

**Evidence:** **E/r2-08-jump-typed.png**, **E/r2-10-jump-input-source.png**, **E/r2-18-agent-confirmation.png**, **E/r2-21-rename.png**, **E/r2-64-sidebar-filter.png**, contrasted with **E/r2-58-recovery-input.png**. Driver calls returned foreground/global-input delivery, not refusal.

**Probable cause [INFERENCE, also suggested by integrator]:** terminal handles committed platform text while Hutan-owned fields derive text from a KeyDown/key code under the active Russian layout. IME, dictation, accent and emoji input may share that risk, **but those were not exercised**. This pass establishes synthesized text corruption, not a universal physical-keyboard failure.

### N3 — Default simple search fields ignore Paste; enabling Vim restores a clipboard path

**Severity: major. Area: picker/sidebar/history input editing.**

**Exact steps:** Set `editor.vim_mode=false` (the default). Open ⌘P and foreground ⌘V with clipboard **Round two**. Repeat in palette, History and sidebar filter. Then enable `editor.vim_mode=true`, reopen/focus the corresponding fields and paste the same kind of query.

**Expected:** Standard Paste works regardless of optional Vim mode.

**Actual:** Vim-off Jump stays empty; History remains on its empty-query hint; sidebar does not receive the pasted query. With Vim enabled, pasted **Settings** filters the palette, **Load shell 32** filters the sidebar, **R2_HISTORY_MARKER** returns History results, and **sleep** filters Resources. The rich Start Command and inline-comment fields accepted Paste even while Vim was off, so clipboard transport itself was not universally broken.

**Evidence:** before/after **E/r2-84-jump-paste-vim-off.png**, **E/r2-81-jump-vim-paste.png**; **E/r2-62-history-search.png**, **E/r2-98-history-vim.png**; **E/r2-64-sidebar-filter.png**, **E/r2-97-sidebar-filter-vim.png**. Successful non-Vim rich input: **E/r2-23-command-paste.png**, **E/r2-32-review-tray.png**. Probable cause [INFERENCE]: simple-field clipboard handling lives only on the Vim-enabled path instead of a shared default edit action.

## 4. Top 10 next fixes

Ordered by impact on these observed journeys. Design choices below are recommendations [INFERENCE], not ten independently demonstrated major bugs.

1. **Make setup truly modal and Escape-safe (N1).** Block underlying workbench and terminal key dispatch for the entire visible setup lifetime. Retest both fresh launch and Run Setup re-entry.
2. **Use the platform committed-text path in every Hutan input (N2).** Preserve Unicode independently of synthetic key codes/layout; expand validation to IME/dictation/emoji before claiming those work.
3. **Provide ordinary Paste with Vim disabled in all simple fields (N3).** Search should not require discovering an unrelated modal-editing preference.
4. **Implement shared Select All/replacement semantics (N4).** Validate actual replacement, not merely the absence of a shortcut error; include Jump, palette and filters in the same behavior matrix.
5. **Repair Resources row menus and exercise a real kill confirmation (N5).** Test both dock-bottom and center-tab placements, mouse ellipsis and right-click, before relying on the panel for runaway-process management.
6. **Finish narrow Changes content adaptation (N6).** Collapse/resize the file list, preserve Commit all and allow deliberate diff access, not just a wrapping top toolbar.
7. **Default the send-confirmation opt-out checkbox to off (N7).** Keep the successful F2 protection until the user deliberately elects to remove it.
8. **Keep backend selector positions stable while readiness loads (N8).** Put installation beside its error/help, outside the backend-choice hit targets.
9. **Reduce recovery-badge competition in a large sidebar [INFERENCE].** Thirty-plus repeated `respawned` badges truncate session/project identity; keep detailed recovery in its working summary while preserving readable names. See **r2-63-sidebar-load.png** and **r2-73-workspace-context.png**. This is a density recommendation, not a measured performance failure.
10. **Expose independent UI input/render latency evidence [INFERENCE].** Current CLI response times are good and the big terminal stayed usable, but multi-second driver overhead prevents credible frame/keystroke latency claims. Retain a repeatable 30-session/200k-line scenario with a direct timing instrument rather than treating Cua call duration as app latency.
