# GPUI standalone spike

## Verdict
**PASS for pinned upstream GPUI on macOS; NOT drop-in compatible with gpui-component HEAD.**
A release app renders a header plus an 80×24 Menlo grid using 24 row text elements, and a real injected `a` key updates the visible counter to 1. It stays alive for 5 seconds without panic. Screenshot: [proof.png](proof.png).
Recommend one exact Zed git revision for both `gpui` and `gpui_platform`, committed Cargo.lock, and deliberate coordinated updates. If gpui-component is required, choose its exact `gpui-pre-*` snapshot ecosystem instead; do not mix those GPUI types with upstream git.

## Pitfalls
- Xcode installed did **not** imply the separate Metal compiler component was installed. Initial error verbatim: `error: error: cannot execute tool 'metal' due to missing Metal Toolchain; use: xcodebuild -downloadComponent MetalToolchain`. No system installation was performed; upstream's supported `runtime_shaders` feature solved this and launched successfully.
- Build warning verbatim: `warning: the following packages contain code that will be rejected by a future version of Rust: block v0.1.6`.
- As requested after the initial failure, [standalone fallback](standalone/Cargo.toml) tried `gpui = { package = "gpui-standalone", version = "=1.4.4", default-features = false, features = ["font-kit"] }`; same window implementation with mirror README bootstrap `gpui::Application::new()` failed after **113.32 s**, exit 101.
- Fallback error verbatim: `error[E0599]: no associated function or constant named \`new\` found for struct \`Application\` in the current scope`; compiler offers `Application::with_platform`. Published 1.4.4 is already split at this API, while [mirror README](https://github.com/gpui-standalone/gpui/blob/main/README.md) still describes `Application::new()`. It is not a proven drop-in standalone fallback. Mirror HEAD manifest now says **1.6.3**; that version was not built.
- Upstream warns of frequent breaking pre-1.0 APIs. Pin **both** GPUI packages and the lockfile; keep the selected ecosystem consistent across every UI dependency. Registry mirrors introduce publisher/snapshot synchronization risk, not semantic compatibility automatically.

## Open questions
- Production frame-time/CPU under sustained terminal updates, scrollback, Unicode width/combining characters, selection and IME remain **[UNVERIFIED]**; this measures static ASCII rows, not a complete terminal renderer.
- Forced same-revision gpui-component integration and gpui-terminal migration require separate porting/compatibility work. A stock component ecosystem using exact gpui-pre 0.3.9 was source-inspected and compiled as a dependency, but not launched as an app here.
- Full download-cold successful build time was not separately measured: the successful 62.30 s figure is explicitly artifact-cold/source-warm; initial download-cold failure and recovery timings are reported separately.
