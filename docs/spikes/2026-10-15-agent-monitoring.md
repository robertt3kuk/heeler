## Consequences for M13
1. **The current reporter cannot carry a tree.** `hutan agent report` (M3-B) has `state ∈ idle|working|blocked`, no node identity, no parent, no model/usage/duration; Claude subagents are a counter in `message`. M13 needs an `AgentObservation` per session: a tree of nodes `{node_id, parent_node_id?, kind main|sub, name, agent_type?, state, outcome?, model?, started_at_ms, ended_at_ms?, current_activity?, usage?: {tokens_in, tokens_out, cache_read, cache_write, reasoning, context_tokens, context_window, cost_usd} (all optional, never zero-filled), source}`.
2. **Separate three things**: runtime state (working / blocked / idle), outcome (completed / failed / interrupted / disconnected), and liveness (process alive / gone). Missing evidence = `unknown`/`disconnected`, never invented.
3. **Usage semantics differ per source** (OMP `tokens` excludes cache reads; Claude `context_window.*` is the latest context, not lifetime; Codex `total` vs `last`). Store as reported with a `usage_kind`, label in UI.
4. Priority: OMP extension + Claude hooks (fully local/docs-verified, terminal sessions — the user's main workflow), Codex via the M4 adapter (Hutan-owned) + `thread_spawn_edges` reconstruction, OpenCode and ACP later.
5. Files/DBs reconstruct trees after the fact (OMP directory nesting + `.tombstone`, Claude `subagents/agent-<id>.jsonl`, Codex `thread_spawn_edges` + `session_meta.parent_thread_id`) but are not authoritative for live state.

## Open evidence gaps
- Claude: `subagentStatusLine` `tasks[].id` ↔ hook `agent_id` equality; which installed version `claude` resolves to.
- Codex: `thread_spawn_edges.status` values; whether one app-server connection can observe threads of other processes (assume no).
- OpenCode: which executable `opencode` resolves to (v1 vs v2) and its live endpoints.
